# QMan Product Requirements Document (PRD) - Summary

## Vision
Digitize and orchestrate patient movement through hospitals, replacing manual shouting and fragmented communication with a seamless, real-time workflow.

## Core Concept
- **Visits, not patients:** Each visit is a unique journey.
- **Journey Code:** (e.g., QM-8F4K) used by patients to track progress on mobile without login.
- **Status Integration:** Sits on top of HMS (Hospital Management System).

## Key User Roles
1. **Receptionist:** Create visits, assign workflows, print journey tickets.
2. **Nurse/Doctor/Clinical Staff:** Call next, complete stage, transfer patients.
3. **Admin/Manager:** Configure workflows, monitor live hospital status, view analytics.
4. **Patient:** Track wait time, position, and next steps via mobile.

## Design Deliverables
- Authentication (Login)
- Admin (Dashboard, Workflow Builder, Settings)
- Reception (Dashboard, Visit Creation)
- Clinical Workspace (Generic, reusable station workspace)
- Manager (Live Dashboard, Analytics, Journey Timeline)
- Patient Experience (Mobile tracking page)
- Public Display (Queue board)
